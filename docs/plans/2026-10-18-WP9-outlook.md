# WP9 Outlook 6-24 h (E8): TDD plan

Source: MVP2 plan WP9 and build plan E8. Branch `feat/outlook`.

## Design

- `floodready/met_parse.py`: `parse_warnings(payload)` turns the saved MET payload (data.gov.my list, as written by
  `jobs.run_met_warnings` to `data/raw/met_warnings/json/<day>/<hhmm>.json.gz`) into land rain warnings:
  title (EN/MS), `valid_from`, `valid_to`, and `areas` = `{state: set(districts)}`. An empty set means the whole state
  ("Selangor" with no bracket). Only titles matching thunderstorm / heavy rain / continuous rain count; the sea warning
  and "No Advisory" are ignored. `names_area(warning, state, district)` is true for the bare state or a listed district.
  Real notices differ: some name "Selangor (Hulu Langat, ...)" without Klang; those do not fire for BBR.
- `floodready/engine/outlook.py`:
  - `township_outlook(met_warnings, forecast, now, cfg) -> Alert | None`. `met_warnings` = parsed warnings, `forecast` =
    DataFrame `time_local, precip_mm` (hourly, row covers [t, t+1h)), `cfg` = rules config plus `township` (`id`, `district`,
    `state`). Fires when a warning overlapping [now, now+24 h] names the state or district, or the forecast sum over
    now+6 h..now+24 h >= `outlook.forecast_6_24h_min_mm` (40). Level Watch, `fired_by=('outlook',)`. Window = the contiguous
    run of forecast hours around the peak hour with >= half the peak hour's rain (when the forecast sum passes the
    threshold), otherwise the warning's validity clipped to [now, now+24 h]. `street_id` carries the township id; the runner
    copies it per street. Reasons: `met_warning` (title) and/or `forecast_rain` (amount), EN and MS, both saying forecasts
    often miss tropical storms. Horizon `outlook` and confidence `medium` are set by the caller (contract).
  - `issue_outlook(candidate, last, now, cfg)`: alert unless the last outlook row is within the 60 min cooldown, none
    while one is already active, and an `all_clear` when the condition ends (so `active` can clear).
- Runner (live only): optional `EngineContext.outlook_inputs(now) -> (warnings, forecast)`; after each live refresh the
  township outlook is expanded to every street whose nowcast level is Normal, stored with `horizon='outlook'`
  (id suffix `~outlook`, same as `repo.insert_alerts(horizon='outlook')`), `push` from `alerts.push_levels`.
  The all-clear covers the streets that had the outlook.
- "Active by horizon": `repo.list_alerts(active=True)`, `GET /alerts?active=true` and `StreetDetail.active_alert` group by
  (street, mode, horizon), so an outlook row never hides a nowcast all-clear and the reverse.

## Tests (written first, seen failing)

1. `tests/test_met_parse.py`: real fixtures: Klang listed, bare Selangor, Selangor without Klang, sea and
   No Advisory ignored, expired warning not active, malay title kept.
2. `tests/engine/test_outlook.py`: E8 acceptance (Selangor MET fixture active for BBR; 45 mm 18:00-21:00 window; 5 mm and
   none; cooldown), forecast outside 6-24 h ignored, warning wins over low forecast, texts mention missed storms (EN/MS),
   all-clear when the condition ends, Selangor-without-Klang no outlook.
3. `tests/db/test_repo.py`: active grouped by horizon.
4. `tests/api/test_runner.py`: live refresh issues outlook only for Normal streets, never in replay, push flag, ids;
   `/alerts?active=true` and street `active_alert` by horizon.
5. `app.py` wiring reads the latest saved MET payload and the latest Open-Meteo `best_match` fetch (BBR point), covered
   by a loader test on tmp files.
